## Kept under the original licences

Gherkin scenarios, step definitions and other code from the six source projects keep the licence of the project
they come from. This applies to the original files and to every excerpt of them inside a record (A1), a prompt (A2)
or a model output (A3), such as a ground-truth step definition, a retrieved example or a class skeleton.

| Source project | Licence (SPDX) |
|---|---|
| Sylius/Sylius | MIT |
| PrestaShop/PrestaShop | OSL-3.0 |
| apache/fineract | Apache-2.0 |
| airslie/renalware | MIT |
| nhsconnect/gpconnect-provider-testing | Apache-2.0 |
| openMF/ph-ee-integration-test | MPL-2.0 |

`data/provenance.jsonl` records, for each source file, the repository, the pinned commit, the path, the SHA-256 hash
and the licence. Every record in A1 has the fields `repo` and `commit`, and every prompt (A2) and model output (A3)
refers to its record by `record_id`, so each excerpt can be traced to its source project and licence.

OSL-3.0 and MPL-2.0 have file-level copyleft terms: if you redistribute these excerpts, keep their provenance and
licence. `THIRD_PARTY_NOTICES.md` has the details.
